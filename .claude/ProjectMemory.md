# ProjectMemory.md — KOF97 逆向魔改工程长期记忆

## 1. 硬件平台与体系架构规范
- **平台**：SNK Neo-Geo MVS (Multi Video System) / AES 街机卡带系统。
- **主 CPU**：Motorola 68000 @ 12MHz（16位数据总线，24位地址总线，运行态为严格大端序 Big-Endian，Word/Long 访问要求偶数对齐）。
- **磁盘 P-ROM 格式**：物理镜像文件按 16-bit 进行了字交换（`bswap16`），分析/反汇编前必须转换，交付前必须还原。
- **协处理器**：Zilog Z80 @ 4MHz（音频处理）。
- **图形芯片**：LSPC2-A2 视频处理芯片，管理 Sprite（点阵精灵图），支持 380 个 16x16 像素瓦片缩放与平铺。
- **调色板位编码（非线性）**：
  `Bit 15: Dark`, `Bit 14: R0`, `Bit 13: G0`, `Bit 12: B0`, `Bit 11~8: R4..R1`, `Bit 7~4: G4..G1`, `Bit 3~0: B4..B1`。
- **内存映射**：
  - `0x000000 - 0x0FFFFF` (1MB)：`KOF97_P1.ROM`（主程序只读存储器）。
  - `0x100000 - 0x10FFFF` (64KB)：Work RAM（主 68K 工作内存，1P 角色结构体 `0x108100`，2P `0x108300`）。
  - `0x200000 - 0x2FFFFF` (1MB 窗口)：`KOF97_P2.ROM`（4MB 分 4 个 1MB Bank 动态切换，调色板位于 Bank 2 `0x2CFFF0`+）。
  - `0x400000 - 0x401FFF` (8KB)：Palette RAM（调色板 RAM，存放 16 位颜色字）。
  - `0xC00000 - 0xC1FFFF`：Neo-Geo 系统 BIOS（`neo-geo.rom`）。

## 2. ROM 芯片文件分布与容量
- `KOF97_P1.ROM` (1,048,576 B) + `KOF97_P2.ROM` (4,194,304 B)：68000 机器码，数值计算、判定盒、人物属性逻辑。
- `KOF97_C1~C4.ROM` (各 8MB) + `C5~C6.ROM` (各 4MB)：合计 **40MB**，4bpp 点阵精灵图像瓦片数据。
- `KOF97_S1.ROM` (128KB)：字符/文本固定层图元。
- `KOF97_M1.ROM` (128KB)：Z80 驱动代码。
- `KOF97_V1~V3.ROM` (各 4MB，合计 12MB)：ADPCM 语音采样。

## 3. 游戏角色状态内存核心结构（Work RAM）
- 引擎中全局基址寄存器 `A5 = 0x108000`，当前正在处理的角色指针常驻 `A4`（1P `0x108100` / 2P `0x108300`）。
- 关键字段偏移：
  - `+$0070(A4)`：角色 ID（草薙京 `0x0000`，八神庵 `0x0018`，大蛇 `0x001E`）
  - `+$0138(A4)`：当前生命值 HP（初始满值 `$0067` / 103 点，受击递减）
  - `+$013E(A4)`：破防槽 Guard Crush（初始满值 `$0067`，受创递减，小于 0 触发破防）
  - `+$0146(A4)`：眩晕槽 Dizzy/Stun（初始满值 `$0067`，受创递减，小于 0 触发眩晕）
  - `+$012E(A4)`：能量点数（Power Gauge）

## 4. 角色调色板与选人立绘内存架构（P2 Bank 2 调色板系统）
- **基准公式**：
  `0x483E + cid * 8 + btn_idx * 2` 存放对应角色与按键槽位的调色板编号 `pal_id`。
  P2 ROM 中物理调色板绝对地址为 `0x2CFFF0 + pal_id * 32`。
- **16 色字物理排布**：
  - `W00`：保留头/透明色（通常为 `pal_id` 本身）。
  - `W01..W15`：15 个有效调色板颜色字（LSPC2 格式）。
- **角色调色板语义结构差异**：
  - 八神庵（0x1B）：`W1..W4` 肤色，`W5..W7` 衬衫，`W8..W11` 红发红裤，`W12..W15` 外套。
  - 大门五郎（0x02）：`W1..W5` 肌肉肤色（5阶梯度），`W6..W11` 柔道服（6阶梯度），`W12` 红头带，`W13..W14` 木屐与白护腕，`W15` 黑腰带。
  - 陈国汉（0x13）：`W1..W5` 肤色面部，`W6..W10` 囚服（5阶梯度），`W11..W12` 铁球铁链，`W13..W15` 大胡子与皮带。
- **选人界面与 HUD 头像调色板（Portrait Palettes）**：
  - 每个角色的调色板块由 16 个调色板组成（512 字节），`base_pid + 0` 为战斗主点阵，`base_pid + 13, 14, 15` 为选人半身立绘与血条旁头像调色板。
  - 选人界面立绘表位于 `0x499C + cid * 8`，指向 `base_pid + 14`。修改此处的服装色阶可实现选人界面立绘与实战皮肤的 100% 联动同步。
- **CPU 敌人与 1P 玩家隔离准则**：
  - 未定制角色（`themeId == "classic"`）必须保持 100% 原始 SNK 字节零修改。
  - 定制角色仅覆盖 Button 0 (A) 与 Button 1 (B) 槽位；Button 2 (C) 与 Button 3 (D) 必须保留官方原版，确保街机 CPU 敌人与 2P 不受玩家换装影响。

## 5. 现代化 Webview 桌面工作台架构（KOF97ModStudio）
- **技术栈**：HTML5/CSS3 深色舞台风格 (Design B) + Python 3 + EdgeChromium (pywebview) + PyInstaller 打包。
- **COM 跨线程死锁防护**：API 桥接类成员全部使用私有属性前缀 `_`，避免 pywebview 递归反射扫描 Windows Forms / COM 控件树；异步日志通过全局窗口句柄 `_APP_WINDOW` 独立派发，彻底杜绝死锁与卡顿。
- **全员独立皮肤存储**：前端与后端均维护独立的角色配置字典 `_character_skins = { char_id: { themeId, colors } }`，支持单角色定制与全量 36 位角色一键批处理。

## 6. 皮肤系统设计准则（防重叠与高明度对比）
- **杜绝丧尸感与杂色重叠**：任何非怪物/非幻象主题，角色的面部与裸露皮肤（如八神面部/手部、大门胸膛与四肢、大猪面容躯干）必须严格锁定官方原版温暖健康肤色（如 `#FFF7B5`, `#F7C584`, `#EF945A`, `#B55229`），严禁通用明度排序导致肤色染绿/染紫。
- **高明度与棱角分明（特瑞标准）**：衣服、内衬与外套必须有强烈的色相和明度反差（例如黑风衣配高光纯白衬衫 `#FFFFFF`，或深色战术服配明亮边缘线），确保在实战与爆气状态下轮廓清晰鲜明。
- **特异化语义调色板**：八神（普通八神 `0x1B` 与暴走八神 `0x1D` 统一语义映射）、大门五郎（`0x02`，6段柔道服阶梯+5段肌肉高光阶梯）、陈国汉（`0x13`，5段囚服阶梯+铁球反光段），均提供量身定制的专属色彩梯级。

## 7. 运行态热更新与内存注入规范（Live Reload）
- **WinKawaks 实时注入机制**：
  - 通过 Win32 API (`OpenProcess`, `VirtualQueryEx`, `WriteProcessMemory`) 挂载正在运行的 `WinKawaks.exe` 进程。
  - **即时生效**：将当前角色的 15 组 LSPC2 颜色直接写入运行态 Palette RAM（`0x400000` 对应的主机缓冲区），画面在下一帧（16.6ms 内）立即刷新，无需退出游戏或重启模拟器。
  - **常驻生效**：同步写入 WinKawaks 内存中已解密的 P2 ROM 调色板基准区（`0x2CFFF0`+），使角色后续回合、重新加载或超必杀爆气恢复时依然继承新皮肤。

## 8. 选人界面隐藏人物全解锁规范（All Hidden Characters Selectable）
- **KOF97 隐藏人物阵容**：
  - 暴走八神庵（Orochi Iori, ID `0x1C`）
  - 暴走莉安娜（Orochi Leona, ID `0x1D`）
  - 真·大蛇队（觉醒七枷社、觉醒夏尔美、觉醒克里斯, ID `0x15..0x17` + `alt_flag=1`）
  - '94 经典草薙京（'94 Kyo, ID `0x00` + `alt_flag=1`）
  - 大蛇（Orochi, ID `0x1E`）
- **解锁实施**：
  1. `p1_be.bin` 偏移 `0x009976`：补丁写入 `4E 71 1B 7C 00 1F 6C 34`（`NOP; MOVE.B #$1F, $6C34(A5)`），将选人网格偏移强制锁定为第 31 号表（指向隐藏角色底行）；
  2. `p1_be.bin` 偏移 `0x01F7C8`：将条件跳转 `67 06` 覆写为 `4E 71`（`NOP`），确保无论是否按键，均执行 `MOVE.B #$1F, $6C34(A5)`；
  3. 大蛇（`0x1E`）网格补全：在全部 8 个选人网格表（`0x0A9499`, `0x0A94C6`, `0x0A94F3`, `0x0A9520`, `0x0A954D`, `0x0A957A`, `0x0A95A7`, `0x0A95D4`）的第 3 行第 4 列（八神 `0x1B` 与真吾 `0x1F` 之间）写入 `0x1E`。
  选人界面无需搓任何按键，第 4 行与大蛇头像直接完整显示且光标可自由悬停选择。

## 9. 核心角色 10 款皮肤精工配色模型与多角色拓展技术规范（Non-Zombie Aesthetic & Multi-Character Mapping）

### 9.1 杜绝丧尸感的根本法则（Anti-Zombie Core Rules）
1. **健康肤色绝对不可动摇（Strict Skin Tone Anchor）**：
   - 角色面部、躯干胸腹、四肢裸露肌肉的调色板字槽位，必须**100% 锁定 SNK 真实健康暖阳色阶**（`#FFF7B5`, `#F7C584`, `#EF945A`, `#B55229`），绝对禁止任何主题将肤色槽位映射为绿、紫、蓝或苍白灰阶。
2. **白衬衫与头带锁在官方原色**：
   - 内衬、眼白、白道服沿用该角色官方调色板里的白阶，不另铺 `#FFFFFF` 高光。八神衬衫是 `#F7F7FF / #BDBDC5 / #737B84`。
3. **换肤只改色相，不改原版明暗（Shade Lock）**：
   - 衣服每一格保留官方槽位的明度和饱和度，只把色相转到主题色。饱和色素（八神红发红裤）不允许比原格更亮，因此不会变成粉彩高光；柔和布料（大门柔道服、草薙京制服、陈国汉囚服）保留原版均匀阶梯，暗部停在原版的深度，不压成近黑。
   - 暴走八神的官方紫阶本身就是「亮部发灰、暗部发死」的反例。给他换肤时改用普通八神的明暗曲线，再套主题色相。
   - `PRESET_THEMES` 里的 15 色是八神预览色，不再直接盖到像素上。

## 11. 站立图拼装（ACT 00）与踩过的坑（2026-11-11）

### 正确规则

- 站立帧来自 ACT 00（P2 指针表 `0x200002`），不要用 image-def 下标 0 当站立图。
- P2 必须先 `bswap16`，再按 68000 大端读。磁盘上的 `00 FF` 在大端里是 `FF 00`。
- 布局头：byte0 调色板，byte1 绘制函数，byte2 `nx`（列数），byte3 `ny`（行数），随后是该函数的 tile 与遮罩数据。
- 遮罩按列；byte 遮罩的 bit7、word 遮罩的 bit15 是最顶行。空列仍占 16 像素 X 槽，空位仍占 Y 槽，**不要** `skip_sparse` 抽列或把列挤在一起。
- 图定义 6 字节：有符号 X、Y，然后 `af`。`af & 0x3FF` 为 C 调用号；`0x4000` 竖翻，`0x8000` 横翻，`0x2000` 表示后面还有一组 6 字节要叠画（如陈国汉）。
- C-ROM 16×16 的四个 8×8 顺序是 TR、BR、TL、BL（`crom_tool.BLOCK_OFFSETS`）。每一行 8 个像素里，**bit 0（LSB）是最左边，bit 7（MSB）是最右边**。`decode_tile_16x16` 与 `encode_tile_16x16` 必须一致。
- 列距在 `zoom_x=15` 时是 16 像素。游戏里 sticky 列距等于前一列的 `(zoom_x+1)`，不是“永远 16”；但站立角色默认 `RoleShrinkRate=0xFFFF`、水平系数 `0xFF` 时仍是满尺寸 16 像素。不要靠乱缩列距去补缝。
- 实现文件：`src/rom/sprite_compose.py`。Studio 中间预览走 `render_idle_png`。

### 踩过的坑（不要再走）

1. 按磁盘未换字的字节序解析布局，遮罩极性反了，再用 `skip_sparse` 抽掉“稀疏列”，人物会碎成竖条。用户拿到的 6:46 exe 截图就是这个样子。
2. 布局改对之后如果还碎，通常不是列距问题。官方水平缩放（MAME skip 表 + `(zoom_x+1)` 列距）收不拢碎块；把列重叠绘制会让躯干叠两层，也不要这么做。
3. 只把左右 8×8 对调（所谓 v6）时，中间会看起来像完整人、两边多出碎块。那是在错误位序（把 MSB 当最左像素）上又等于把整块图左右翻转，不是正确解码。
4. `crom_tool` 自测里的 “Real MVS C-ROM hardware data bit-exact” 只是 encode↔decode 往返，不能证明屏幕方向对。视觉基准要用 arcade-sprite-viewer 的 `kof97.gfx`：文件头小端 `0x05267234`，从第 16 字节起是 gzip；解压后每块 128 字节，每字节高半像素在左。
5. 预览背景 `#151720` 太暗，拼对之后的黑道服也会看起来发虚。`hero-stage` 中心已提到 `#2E3140`。不要把对比度问题当成拼装错误。
6. 根目录 `KOF97ModStudio.exe` 在 Studio 还开着时无法覆盖。新包在 `dist\KOF97ModStudio.exe`。不要把仍被占用的旧 exe 提交上去。
7. 工程路径 `D:\TEmp\REA\Fighter97` 对文件拷出工具来说可能在允许根目录之外，先拷到 `C:\Users\mimovr\agent-tools\` 再传。PowerShell 不要用 `&&`，用 `;`，带引号的命令写成脚本更稳。
8. 不要改已经认可的明暗生成器；不要写官方 ROM 目录；特效颜色归 KOF97特效，不要和这套换肤 / Studio 工作混改。

## 13. 全员自然染色算法（OKLCH Natural Cloth Painter，2026-11-11 用户实机确认为最终标准）

### 13.1 为什么直接套 Tailwind 色阶或纯 HSV 转色相不够自然
1. **荧光色问题**：网页 Tailwind 色板在 OKLCH 空间里的彩度（Chroma, `C`）高达 `0.18~0.21`，直接套在 15 色像素立绘上会变成刺眼的荧光色（如神乐变成荧光绿）。实测 SNK 官方 B/C/D 换色（如神乐、山崎龙二的 B/C/D 键）：
   - 浅色衣物（白衣换色）的 OKLCH 峰值彩度仅 `0.04~0.105`；
   - 中间调衣物约 `0.07~0.11`；
   - 深色西装/长裤约 `0.07~0.13`。
2. **明暗与上下装对比丢失**：若用固定色阶区间直接覆盖原槽位明度，会把白上衣压暗、黑裤子提亮，导致整个人物上下装融成同一块颜色，丧失原画的布料立体感与深浅层次。
3. **无彩色衣物无法靠纯色相旋转上色**：纯白（神乐上衣、金家藩道服）、纯黑/深灰（龙二西装、八神外套）原槽位饱和度接近 0，仅旋转色相不会变色。

### 13.2 核心算法（`src/palette/costume_painter.py` 中的 `_paint_costume_natural` 与 `_natural_cloth_word`）
全员 36 名角色（`0x00..0x23`，含八神庵、暴走八神、大门五郎、陈国汉、神乐千鹤、山崎龙二等）统一走 `_paint_costume_natural`：

1. **部位分组与色源映射（`_NATURAL_GROUPS`）**：
   - `skin`（皮肤）、`white_trim`（锁定的纯白内衬/绑带）、`contour`（纯黑勾边 `0x0000`）保持官方原色不动。
   - `primary`、`dark_anchor`（衣服、裤子、外套、鞋靴）走主题 `primary` 色阶。
   - `hair`、`accent`（头发、头带、腰带、饰品）走主题 `accent` 色阶。
2. **按明度断层自动拆分上下装（`_cluster_slots`）**：
   - 同一部位组内按原槽位明度排序；相邻槽位明度差 `> 0.24` 时自动拆成独立衣物簇（例如神乐 `primary` 自动拆成白上衣簇与黑裤子簇），每件衣物各自计算明暗偏置（`light` / `full` / `dark`）。
3. **区分原画有色部位与无彩色部位（`keep_shine`）**：
   - 若簇内超过 45% 的槽位原本就有颜色（`keep_shine = True`，如八神红发、不知火舞红衣）：簇内纯白高光点（`sat <= 0.12 and val >= 0.90`）视为镜面反光保留原白；色相与基准彩度直接取 `THEME_KEYS[theme_id]` 的主/辅标志色。
   - 若簇内原本是白/灰/黑无彩色布料（`keep_shine = False`，如神乐白衣、龙二黑衣、大门/大猪道服、八神黑外套）：所有槽位均参与染色，色相与基准彩度按槽位在簇内的明暗次序从 `THEME_RAMPS[theme_id]` 采样。
4. **锁死原画 OKLCH 明度 `L` + 钟形彩度封顶（`_natural_cloth_word`）**：
   - 将原槽位 RGB5 转到线性光再转 `OKLCH(src_l, src_c, src_h)`。
   - **明度 `lum`**：严格保留原槽位 `src_l`（极暗槽位 `src_l < 0.16` 轻微缓和为 `0.16 + (src_l - 0.16) * 0.5` 以免死黑吞没染色；`light` 浅色簇顶格压到 `min(lum, 0.97) - 0.02 * lum`，让纯白顶格也能挂上淡淡的米色/薄荷色，与 SNK 官方神乐 D 键一致）。
   - **彩度封顶 `chroma`**：按明度钟形曲线 `_cloth_chroma_cap(lum, bias)` 计算官方布料彩度上限（峰值 `_CLOTH_CHROMA_PEAK = {"light": 0.105, "full": 0.11, "dark": 0.13}`，乘以 `1.0 - ((lum - 0.5) / 0.55) ** 2` 让高光和深影自动收敛彩度）。若原槽位本身就是高饱和色（如八神红发 `src_c` 较高），允许上限放宽至 `min(src_c, 0.20)`；最终取 `min(ramp_c, ceiling)`，保证银色/暗忍等低饱和主题依然是银灰色。
   - **头带/腰带转浅色主题时的明度补偿（`lift_neutral`）**：仅对 `accent` 组启用；当原本鲜艳的头带/腰带遇到白色/银色辅色主题导致彩度大幅下降时，按彩度损失比例向同 HSV 明度的中性灰 `gray_l` 抬升 `lum`，使红头带在白色主题下变成干净的白色而非暗灰。
   - **sRGB 色域二分回退（`_oklch_word`）**：合成 `OKLCH(lum, chroma, ramp_h)` 后转回线性 sRGB，若超出 `[0, 1]` 色域则保持 `lum` 和 `ramp_h` 不变，二分降低 `chroma` 直至落入色域，再量化为 LSPC2 16 位调色板字。
5. **四键独立生成**：`generate_harmonious_character_palette(cid, theme_id, p1_data, p2_clean, btn_idx)` 对 `btn_idx = 0..3`（A/B/C/D 四键）各自读取该键自己的官方 15 色作为 `orig_words`（暴走八神借用普通八神同键的服装明暗曲线）。

## 14. 技能特效调色板与 68000 动态受击变色系统（`TASK-STUDIO-019`，2026-11-13）

### 14.1 角色技能特效映射与独立发光着色器
- **主表查找**：必须通过 `P1 0x004956 + pal_idx * 2` 直接查表（`0x15..0x17` 与 `0x18..0x1A` 顺序交错，不可使用线性公式），取得 `vfx_base_pid`（`0x09C0..0x0BE0`）及连续 16 槽（载入 Palette RAM `0x30..0x4F`）。

- **发光渐变着色（`recolor_vfx_palette`）**：与冻结的布料着色器完全隔离；`src_l >= 0.90` 与 `0x7FFF` 保留白炽高光核，中高段放开霓虹饱和度至 `OKLCH C ≈ 0.17..0.25`，支持 10 种 VFX 预设（含 `classic`、`sync_skin`、`cangyan_blue`、`mingyan_purple`、`holy_gold`、`jade_venom`、`crimson_flame`、`aurora_cyan`、`sakura_plasma`、`void_ember`）。

### 14.2 命中敌人后受击变色/附着火焰/感电/火花动态同步（`P1 0x0F0000`）
- **为什么不能静态改动 P2 `0x0000..0x00FF`**：`P2` 公共区 `0x0050..0x006F` 为对战双方共用效果色板（`0x004358(0)` 开局加载一次），静态修改既违反「界面公共色板保持官方原样」约束，也无法支持 1P/2P 不同特效配色（或一方改色、一方 `classic`）。
